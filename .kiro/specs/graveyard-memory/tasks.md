## Rules for every task

- **One task per Kiro run.** Start a fresh run for each task, do only that task, and stop when its tests pass. Do not start the next task in the same run.
- **Targeted tests per task.** Each task names its test files and the exact command to run them (`npx vitest run <files>` in `apps/web`, or the Playwright command it names), followed by `npm run typecheck` and `npm run lint` at the repo root. All of these must pass at the end of the task. The full suite (`npm test` at the repo root) is run by the reviewer at each batch's "done" line, and by the tasks that say so.
- **Never weaken a test.** No task may break an existing test. When a task changes an existing test, it names it under "Existing tests", and only in the way described there; no other existing test may change in that task. A failing test or property is fixed in the source it checks, never by loosening an assertion, filtering a generator, lowering `numRuns`, adding `.skip`/`.only`/`.todo`, or deleting a case. A task never needs a later task to make its own tests pass.
- **Stop and explain on a conflict.** When `requirements.md`, `design.md`, this file, a steering file or an existing test disagree, or a task cannot be done as written, stop. Do not pick a side or work around it: record the conflict, the files and lines involved and the options in the task notes, and end the run. Do not edit `requirements.md` or `design.md`.
- **Do not commit.** Leave all changes in the working tree for review.
